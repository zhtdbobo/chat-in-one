## chat-in-one 桌面客户端

一个支持多家大模型服务商、OpenAI 兼容协议、MCP 工具和技能系统的本地桌面聊天应用，基于 Electron + 原生 JS 实现。

当前版本：`v1.2.5`（Windows x64）

### v1.2.5 更新

- 服务商设置新增「模型目录」：一行一个模型，左侧是发送给接口的模型 ID，右侧是界面显示名称（留空显示 ID）；行尾「>」展开只读能力信息（上下文窗口、最大输出上限、输入类型），垃圾桶图标移除模型，「恢复默认模型」清空当前目录
- 「获取可用模型」拉取服务商列表后弹出「选择要添加的模型」：可搜索、可全选，点「添加所选」才写入目录，点「取消」不改动现有配置；目录里的模型就是主界面模型选择器与对比列表中可选的模型
- 渲染器核心拆分为独立模块（请求生命周期、长文本分块、模型参数覆盖）；流式回复改为按请求 ID 路由，对比模式与并发请求互不干扰，错误在收到响应头之前也能正确归属
- 停止按钮一次停止所有待处理与生成中的请求；生成过程中显示已接收字符数、首个回复片段耗时与总耗时，15 秒没有新片段时给出等待提示
- 对话设置改为温度与 Top P 数字输入：留空使用服务端默认，手填值按「服务商 + 模型」分别保存；移除历史条数与最大输出限制，改为发送全部历史、输出长度由服务端决定；也不再提供流式输出开关，客户端自动识别 SSE 流式与完整 JSON 回复
- 长文本：超过 30,000 字符的消息按约 20,000 字符分段显示，可翻段查看；复制、保存与导出仍保留全文。连续 3 分钟没有数据才结束生成，服务端报错、提前断流或手动停止时保留已收到内容与原因
- 代码块新增「预览」按钮：在独立沙箱页面中运行并回传控制台输出，支持 JavaScript、CSS、HTML 与完整 HTML，按代码块语言选择渲染方式
- 新增浏览器版 Highlight.js 构建脚本（`npm run build:assets`，生成 36 种常用语言），并接入启动与打包流程
- 新增渲染器冒烟测试与长文本压力测试（`npm run test:electron` / `npm run test:stress`），并补充渲染器回归、流式回归等单元测试

### 功能特性

- **多服务商 / 多模型**
  - 在「设置 → 模型服务商」中配置任意数量的 Provider（OpenAI、DeepSeek、阿里云 DashScope、MiniMax 等）
  - 支持 OpenAI 兼容的 `/v1/chat/completions` 接口
  - 支持从 `/models` 拉取模型列表并勾选加入「模型目录」，或手动录入模型 ID；目录里可改模型 ID 与显示名称、展开查看只读能力信息
  - 主界面右下角可搜索切换当前会话使用的模型

- **流式对话体验**
  - 采用 SSE 流式输出，边生成边显示
  - 支持「思考过程」展示（针对 R1 等 reasoning 模型）
  - 支持联网搜索开关（有能力的模型可以用它获取最新信息）

- **响应统计信息**
  - 每条助手回复结尾会显示一行统计：
    - `word count`：本条消息的词数
    - `tokens used`：本次请求消耗的 token（来自接口返回的 `usage`）
    - `first token latency`：首个 token 延迟（请求发出到第一 token 抵达的毫秒数）
    - `model`：实际使用的模型名
    - `time`：回复完成的本地时间（HH:mm）

- **代码阅读友好**
  - Markdown 渲染 + Highlight.js 代码高亮
  - **每个代码块右上角有单独的复制按钮**，只复制该段代码
  - 整条消息右侧还有整体复制按钮，复制整条回复内容

- **对话管理**
  - 支持多会话侧边栏、会话重命名（首条消息自动生成标题）
  - 支持对话导出 / 导入（JSON）

- **MCP & 技能系统**
  - MCP：在设置中添加 MCP 服务器，为模型提供外部工具能力（搜索、文件等）
  - Skills：预设系统提示（System Prompt），在主界面快速切换「搭档」人格

### 环境与运行

#### 依赖

- Node.js（建议 20+）
- npm 或 pnpm
- Windows 10/11 x64

#### 安装依赖

在项目根目录（本 README 所在目录）执行：

```bash
npm install
```

#### 开发模式运行

```bash
npm start
```

将启动 Electron 应用并加载本地前端。

#### 打包

```bash
npm run pack
npm run dist
```

`npm run pack` 生成免安装目录，`npm run dist` 生成 Windows NSIS 安装包。

#### 发布新版本

自动更新靠 Release 里的 `latest.yml` 判断版本，所以「版本号 → 打包 → 建 Release」三件事都要做，产物一个都不能漏。

1. **改版本号和更新说明**
   - `package.json` 的 `version`：客户端比对这个值，必须比线上版本大。
   - 本文件顶部的「当前版本」和「### vX.Y.Z 更新」列表。

2. **提交并跑测试**

   ```bash
   npm test
   npm run test:electron
   git add -A
   git commit -m "release: vX.Y.Z"
   ```

3. **打包**

   ```bash
   npm run dist
   ```

   `dist/` 里生成三个文件，`latest.yml` 是自动更新清单，**漏传客户端就检查不到更新**：

   | 文件 | 用途 |
   | --- | --- |
   | `chat-in-one-Setup-<version>.exe` | 安装包 |
   | `chat-in-one-Setup-<version>.exe.blockmap` | 差量更新 |
   | `latest.yml` | 自动更新清单 |

   `npm run dist` 会先执行 `npm run clean` 清空 `dist/`，需要留旧包就先拷贝出去。`npm run publish` 没有 pre 钩子，若刚升级过 Highlight.js 依赖，先跑一次 `npm run build:assets`。

4. **发布 Release**（三种方式任选）

   ```bash
   git tag vX.Y.Z
   git push origin master --tags
   gh release create vX.Y.Z "dist/chat-in-one-Setup-X.Y.Z.exe" "dist/chat-in-one-Setup-X.Y.Z.exe.blockmap" "dist/latest.yml" --title "vX.Y.Z" --notes "见 README 的 vX.Y.Z 更新"
   ```

   - `gh release create` 建出来的 Release 直接是已发布状态，会触发 `.github/workflows/sync-to-gitee.yml`，把 tag 和三个产物镜像到 Gitee。
   - 也可以 `GH_TOKEN=<有 repo 权限的 token> npm run publish`（即 `electron-builder --win --publish always`）。它只认 `GH_TOKEN` / `GITHUB_TOKEN` 环境变量，不读 `gh` 的登录态，而且创建的是 **Draft** Release，需要再去 GitHub 点一次「Publish release」。
   - 或者在 GitHub 网页手动建 Release、拖入那三个文件，最后点「Publish release」。

5. **验证更新**

   - 已安装的旧版本打开「关于 → 检查更新」，应能查到新版本并下载、重启安装。
   - 更新链路是先走 `gh-proxy.com` 镜像的 generic feed（读取 `latest.yml`），失败后回退 GitHub 官方源，见 `src/js/main/updater.js`。
   - 检查更新只在打包版生效（`app.isPackaged`），开发模式不会检查。
   - Release 停留在 Draft 时 `releases/latest/download` 取不到产物，客户端会检查失败。

> 安装包未做代码签名，Windows 可能提示「未知发布者」，要消除需要配置代码签名证书。`GH_TOKEN` 用环境变量传递，不要提交进仓库。

### 配置模型服务商

1. 打开应用右下角「设置」，进入 `模型服务商` 标签页。
2. 左侧点击「+」添加一个服务商，右侧填写：
   - **服务商名称**：自定义显示名，例如 `OpenAI`、`DeepSeek`、`阿里云 Coding Plan`
   - **API Key**：对应服务商的密钥
   - **API Endpoint**：
     - OpenAI：`https://api.openai.com/v1`
     - 阿里云 Coding Plan：`https://coding.dashscope.aliyuncs.com/v1`
     - 其他 OpenAI 兼容服务请填写它们的 `/v1` 根路径

3. 「模型目录」里一行一个模型，有三种维护方式：
   - **获取可用模型**：点击后调用 `{endpoint}/models` 拉取列表（仅对支持该协议的服务商有效），并在「选择要添加的模型」弹窗中勾选要添加的模型（可搜索、可全选），点「添加所选」后才会写入目录；点「取消」不改动现有目录。
   - **手动新增模型**：在「手动新增模型 ID」输入框中填入模型 ID（如 `MiniMax-M2.5`、`qwen2.5-coder` 等），点击「新增模型」。
   - **编辑与移除**：左侧输入框是发送给接口的模型 ID，右侧输入框是界面显示名称（留空时显示模型 ID）；点行尾「>」展开该模型的只读能力信息（上下文窗口、最大输出上限、输入类型），点垃圾桶图标把模型从目录移除。

4. 目录里的模型就是主界面模型选择器与对比列表中可选的模型。被移除的模型可以再次「获取可用模型」找回；「恢复默认模型」会清空当前目录与显示名称，需要重新获取或手动新增。

#### 测试连接（用于不确定是否真正兼容的服务）

在服务商配置中点击 **「测试连接」**：

- 会弹出一个**模型选择弹窗**，列出当前模型目录中的模型（以及你手动输入的模型 ID）
- 点击某个模型即发起一次测试请求：
  - `POST {endpoint}/chat/completions`
  - Body：`{ model, messages:[{role:"user",content:"ping"}], max_tokens:1, stream:false }`
- 结果会展示在表单下方，包括：
  - 成功或失败（OK / FAIL）
  - 往返延迟（latency）
  - 实际返回的 `model`
  - `usage`（如果服务端有返回）

> 如果服务商不是 OpenAI 兼容协议（路径、鉴权或字段完全不同），测试会失败，这属于预期情况，可以据此判断是否需要写单独的适配层。

### 聊天界面说明

- **模型选择**：主界面输入框下方右侧，可搜索所有可见模型；选择后仅影响当前会话。
- **对话设置**：只提供温度与 Top P 数字输入框，占位符提示服务端默认值；留空时不发送相应参数，使用服务端默认。
  - 删除历史消息数量和最大输出 Token 的手动设置。普通对话与对比模式均发送全部相关历史，不自动按条数裁剪；不指定输出长度，实际输出限制由服务端决定。旧对话保存的消息数量和输出限制会被忽略，不把模型输出上限作为默认请求参数。
  - 模型目录中每个模型可通过「>」展开只读能力信息（上下文窗口、最大输出上限、输入类型），默认收起。「未提供」表示未获取到信息，不代表输出无限制或模型不支持图片；实际限制由服务端决定。
  - 切换模型时同步更新参数范围和默认值；手动温度与 Top P 按服务商和模型分别保存，切换回来会恢复。系统提示词属于当前对话的公共设置。
  - 打开对话设置时自动读取服务商的模型列表信息，回显接口公开的默认值、参数范围和上下文窗口。未返回默认值时显示「未提供」，不会将模型建议值或输出上限当作默认值。
  - 默认值仅显示为提示，手填数字后才会覆盖。对比模式会显示各模型的默认值，手填数值须满足所有所选模型的范围。点击「恢复默认」后保存可清空已有覆盖。
  - 服务端明确标注不支持或固定的参数不可编辑；元数据读取失败时仍可留空使用服务端默认或手动输入。具体元数据以服务商接口为准，例如 [OpenRouter 模型列表字段](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。
- **回复格式**：由服务端默认行为决定，不再提供流式输出开关；普通对话和 MCP 两轮请求均不发送 `stream` / `stream_options`，旧对话保存的开关会被忽略。客户端自动识别 SSE 流式回复与完整 JSON 回复；服务端返回完整回复时，收到完整内容后显示。
- **思考过程开关**：
  - 输入框下方左侧「大脑」图标
  - 开启后，如果模型返回 `reasoning_content`，会以可折叠的「思考过程」区块显示。
- **联网搜索开关**：
  - 输入框下方左侧「地球」图标
  - 开启后，系统 Prompt 会注入提示，引导模型使用联网能力（具体是否生效取决于后端模型与工具）。
- **统计信息**：
  - 每条助手消息底部会有一行：
    - 字数、Token 数量、首个回复片段耗时、总耗时、模型与时间
    - 「首个回复片段」从开始请求算到收到第一段可显示的回答或思考内容；「总耗时」算到生成结束、停止或发生错误。旧对话没有总耗时记录时不会补造数值。
  - 不参与复制代码块的内容，只是可视化信息。
- **长输入与长输出**：
  - 上下文估算仅作提醒，完整输入仍会发送，真实输入限制由服务端校验。
  - 超过 30,000 字符的消息按约 20,000 字符分段显示纯文本，可翻段、跳转或查看最新内容；复制、保存与导出保留全文。
  - 生成中显示已接收字符数与耗时，15 秒未收到新片段会显示等待提示。连续 3 分钟没有网络数据会结束连接并提示，持续返回数据的长生成没有总时长限制。
  - 服务端报告输出长度上限、连接提前关闭、超时或手动停止时，保留已收到内容并显示原因。服务端输出上限仍需通过分章节或发送「继续」处理。

### MCP 与技能（可选）

- **MCP（Model Context Protocol）**
  - 在「设置 → MCP 服务器」中添加 MCP server（命令 + 参数）
  - 主进程会通过 MCP SDK 连接、拉取工具列表，并在请求时作为 `tools` 提供给模型

- **技能（Skills）**
  - 「设置 → AI 技能」中可以配置多个 system prompt，例如：
    - 通用助手、代码专家、翻译官等
  - 在主界面可以快速选择技能，自动覆盖当前对话的 system prompt

### 数据存储与导出

- 所有设置与对话记录存储在用户目录下（通过 `electron-store` 或内置 JSON 存储）。
- API Key 通过操作系统提供的 Electron `safeStorage` 加密后落盘；更换服务商域名时需要重新输入密钥。
- 左侧侧边栏支持：
  - **导出对话**为 JSON
  - 从 JSON 文件 **导入对话**

### 常见问题

- **Q: 某个服务商测试连接失败怎么办？**  
  A: 首先确认 Endpoint、API Key、模型 ID 正确；如果是非 OpenAI 兼容协议，当前版本不会自动适配，需要你在网关层做协议转换。

- **Q: 为什么有的返回没有 `tokens used`？**  
  A: 只有在服务端支持并返回 `usage` 字段时，才能显示 token 统计；否则会显示为 `—`。

- **Q: 为什么中文回复的 `word count` 看起来不太准？**  
  A: 中文按汉字计数，其他内容按空白分词。这是界面字数统计，不是服务端 Token 数量。

### 开发提示

- 主要代码入口：
  - `main.js`：Electron 主进程，负责窗口、IPC、流式请求等
  - `preload.js`：向渲染进程暴露 `window.api`
  - `src/js/*.js`：渲染进程的 UI 与逻辑（聊天、设置、MCP、技能等）

### 回归测试与资源构建

- `npm test -- --runInBand`：131 项 Jest 测试，覆盖主进程、请求状态、上下文压缩、附件格式、模型参数、长文本缓存、回复格式自动识别、流式结束与 MCP 取消。
- `npm run test:electron`：在隐藏的 Electron 窗口中运行 61 项页面检查。测试使用临时用户目录和模拟 IPC，不读取真实设置，也不请求模型服务。
- `npm run test:stress`：8 个客户端压力场景，覆盖百万及 500 万字符输入/输出、非流式长回复、服务端完成后保持连接、提前断流、无数据超时、停止与双模型对比。使用真实渲染器、preload、IPC 和本机 HTTP 模拟服务，并校验完整内容、文件保存、重新加载和页面响应。用户数据在隔离临时目录中，不调用真实模型接口；500 万字符是当前测试规模，不代表客户端绝对上限或模型可输出的字数。
- `npm run build:assets`：从已安装的 Highlight.js 生成浏览器脚本和 36 种常用语言。启动与打包前会自动执行；生成文件位于 `src/js/vendor/`。

请求在发送前登记唯一 ID；普通聊天和对比聊天都能在等待响应时停止。对比聊天按服务商与模型分别保存响应和历史，所有请求结束后恢复发送。错误与停止状态会随对话保存。旧版记录没有服务商标识时，只能按已有模型名兼容匹配。

上下文压缩会合并已有摘要，保留最近六条消息及压缩期间追加的消息；失败或历史被修改时保留原记录。设置最大消息数时，摘要仍会随请求发送。

附件支持 PNG/JPEG/GIF/WebP、UTF-8 文本及 PDF。文本会解码后作为正文发送；图片和 PDF 会检查服务商保存的模型能力。PDF 使用 Chat Completions 的 `file` 输入字段，服务商还需支持此字段；其他二进制格式会在发送前提示转换。文件 token 数量只能粗略估算，实际以服务端统计为准。字段格式参考 [OpenAI 文件输入说明](https://developers.openai.com/api/docs/guides/file-inputs)。

代码预览支持内联 HTML、CSS 和 JavaScript，控制台消息会返回预览面板。预览使用独立页面与嵌套沙箱，无法访问应用 API，外部网络资源受 CSP 限制。
